# 예약 알림 자동 발송 (n8n)

`outing_alert_workflow.json`은 n8n Cloud에서 10분마다 실행되는 예약 알림 워크플로우입니다.

## 흐름

```
Every 10 Minutes (스케줄)
→ Config (배포 주소, 키)
→ Get Due Alerts      GET /api/internal/alerts/due
→ Split Alerts        알림별로 나누기
→ Get Weather         Open-Meteo: 현재 기온, 도착 시각까지 강수확률
→ Get Travel Time     카카오모빌리티 자동차 길찾기: 이동 시간
→ Decide              조건(비/기온) 확인, 출발 권장 시각 계산, 발송 여부 결정
→ Should Send?
   ├ true  → Dispatch          POST /api/internal/alerts/{id}/dispatch
   └ false → Wait Next Cycle   다음 주기에 다시 확인
```

발송 시점의 AI 문구 생성, 카카오 토큰 갱신, 카카오톡 발송, 중복 발송 방지는 백엔드 `dispatch` API가 처리합니다.

## 발송 규칙

등록된 알림은 발송 요건을 충족하면 카카오톡 ‘나와의 채팅’에 도착합니다. 워크플로우는 10분마다 발송 대상과 조건을 확인합니다.

알림은 두 종류입니다.
- `trip`: 약속·외출. 도착지와 도착 시각 기준으로 출발 알림
- `reminder`: 정해진 시각 알림. 매일(`daily`)·평일(`weekdays`) 반복과 날씨 조건 지원

| 구분 | 규칙 |
|---|---|
| 확인 시작 | 알림의 `notify_at`이 지나면 `due` 목록에 포함 (trip 출발 알림은 도착 2시간 전부터) |
| reminder | 설정 시각 `notify_at` 이후 실행 주기에 조건을 확인해 발송. 날씨는 `location` 좌표 기준 (없으면 서울) |
| 반복 알림 | 발송 후 백엔드가 `notify_at`을 다음 날(평일 반복은 다음 평일)로 옮김 |
| reminder 조건 미충족 | 발송 시각 1시간 뒤까지 10분마다 재확인. 그래도 못 보내면 반복 알림은 다음 날로, 1회 알림은 만료 |
| 출발 알림 | 출발 권장 시각 = 도착 시각 − 이동 시간 − 여유 10분, 그 10분 전부터 발송 |
| 이동 시간을 못 구한 경우 | 도착 60분 전에 발송 |
| 조건 형식 | `{"type": "temperature" \| "precipitation", "op": "<" \| "<=" \| ">" \| ">=", "value": 숫자}` |
| 기온 조건 | 현재 기온을 `op`, `value`로 비교 (예: `temperature < 0` = 영하일 때) |
| 강수 조건 | 실행 시각 1시간 전부터 trip은 도착 시각까지, reminder는 실행 시각 12시간 후까지의 시간대별 강수확률 최댓값을 비교. `>`·`>=` 조건은 현재 강수량이 있어도 충족. 사용자 지정 확인 범위는 추후 기능으로 검토 |
| 조건 미충족 | 발송하지 않고 다음 10분 주기에 다시 확인 |
| 만료 | 도착 시각이 지날 때까지 발송되지 않으면 백엔드가 `expired`로 변경 |
| 중복 방지 | 백엔드가 트랜잭션으로 알림을 선점하고, 발송 후 `sent: true` 기록 |

## 설정 방법

1. n8n Cloud에서 **Workflows → Import from File**로 `outing_alert_workflow.json`을 불러옵니다.
2. **Config** 노드에서 세 값을 바꿉니다.
   - `base_url`: Render 배포 주소 (예: `https://ai-outing-talk.onrender.com`, 끝에 `/` 없이)
   - `internal_api_key`: 백엔드 환경변수 `INTERNAL_API_KEY`와 같은 값
   - `kakao_rest_api_key`: 카카오 REST API 키 (이동 시간 조회용)
3. 상단의 **Test workflow**로 한 번 실행해 각 노드 결과를 확인합니다.
4. 문제가 없으면 오른쪽 위 **Active**를 켭니다.

## 운영 환경

- n8n Cloud 무료 체험판 (14일, 실행 1,000회)
- 로컬 n8n은 컴퓨터가 꺼지면 멈추므로 Cloud 사용
- 10분 간격 = 하루 144회. 수동 테스트 실행도 횟수에 포함되므로 필요한 만큼만 실행
- Render 무료 서버는 15분 동안 요청이 없으면 잠들지만, 10분마다 호출하므로 대부분 깨어 있음. 재배포 직후를 대비해 HTTP 노드 타임아웃 90초, 재시도 설정

## 증거 자료

- 워크플로우 화면 스크린샷
- **Executions** 탭의 성공 실행 기록 스크린샷
- 수신된 카카오톡 메시지 스크린샷
- 아래 테스트 결과표

## 자동 발송 테스트

| # | 시나리오 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | 알림 시각을 직접 지정 ("20분 뒤에 알려줘" 등) | 다음 주기에 수신 | |
| 1-1 | 매일 반복 + 기온 조건 ("매일 아침 7시 반에 영하면 패딩") | 조건 충족 시 수신, 목록에 다음 알림 시각이 하루 뒤로 표시 | |
| 2 | 비 조건 + 강수확률 높은 날 | 수신 | |
| 3 | 비 조건 + 맑은 날 | 수신되지 않음, Wait Next Cycle로 이동 | |
| 4 | 출발 알림 (도착 1시간 30분 뒤 약속) | 출발 권장 시각에 이동 시간 포함해 수신 | |
| 5 | 같은 알림이 두 주기 연속 대상 | 한 번만 수신 (`already_sent`) | |
| 6 | 백엔드가 잠든 상태에서 실행 | 타임아웃 없이 발송 | |
| 7 | Access Token 만료 후 (로그인 6시간 이후) | 토큰 갱신 후 정상 발송 | |
