# 기능요구 명세서


## 1. 개요

### 1-1. 서비스 정의

| 항목 | 내용 |
|---|---|
| 서비스명 | 외출톡 (AI Outing Talk) |
| 한 줄 정의 | 외출 계획을 문장으로 입력하면 AI가 해석해 출발 시각을 계산하고, 카카오톡으로 알림을 보내는 서비스 |
| 배포 주소 | https://ai-outing-talk.onrender.com/ |
| 대상 사용자 | 약속과 출퇴근이 잦아 출발 시각을 자주 가늠해야 하고, 카카오톡을 일상적으로 사용하는 사용자 |

### 1-2. 해결하려는 문제

외출 준비에는 날씨 확인, 이동 시간 확인, 출발 시각 계산이 매번 필요하다. 정보는 이미 존재하지만 사용자가 직접 여러 앱을 오가며 이어 붙여야 하고, 그 과정에서 출발 시각을 놓치거나 준비물을 빠뜨린다.

### 1-3. 핵심 AI 활용

| 시점 | AI가 하는 일 |
|---|---|
| 알림 등록 시 | 한 문장에서 출발지, 도착지, 도착 시각, 날씨 조건을 해석한다 |
| 알림 발송 시 | 그 시점의 날씨와 이동 시간을 반영해 보낼 알림 문구를 생성한다 |

### 1-4. 우선순위 기준

- Must: 과제 평가 필수 기능. 문서에 기재된 대로 동작해야 한다.
- 확장: Must 구현 이후 추가한 기능.

### 1-5. 용어

| 용어 | 뜻 |
|---|---|
| 출발 알림 (trip) | 도착 시각을 기준으로 이동 시간을 반영해 출발 시각에 보내는 알림 |
| 시각 알림 (reminder) | 사용자가 지정한 시각에 보내는 알림 |
| 조건 알림 | 날씨 조건을 만족할 때만 발송하는 알림 |


## 2. 기능 요구사항

### 2-1. 필수 기능 (Must)

| ID | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| M1 | 개인정보 동의 | 서비스 이용 전 수집 항목, 이용 목적, 보관 기간을 안내하고 동의를 받는다. | 동의하지 않으면 로그인 화면으로 넘어가지 않는다. |
| M2 | 카카오 로그인 | 카카오 계정으로 로그인하고 메시지 발송 동의(`talk_message`)를 함께 받는다. | 로그인 후 서비스 화면으로 이동하고, 세션 쿠키로 사용자가 식별된다. |
| M3 | 자연어 알림 등록 | 외출 계획을 한 문장으로 입력하면 AI가 출발지, 도착지, 도착 시각, 조건을 해석해 알림으로 저장한다. | 문장 입력 후 해석 결과가 알림 목록에 표시된다. |
| M4 | 장소 좌표 변환 | 해석된 장소명을 카카오 Local API로 좌표로 변환한다. | 알림에 출발지와 도착지의 좌표가 저장된다. |
| M5 | 출발 시각 판단 | 날씨와 이동 시간을 반영해 알림 발송 시점을 결정한다. | 도착 시각 기준으로 알림 시각이 계산되어 표시된다. |
| M6 | 알림 목록 조회 | 등록한 알림과 상태를 목록으로 확인한다. | 로그인한 사용자 본인의 알림만 표시된다. |
| M7 | 카카오톡 알림 발송 | 알림 시각이 되면 카카오톡 나에게 보내기로 사용자 본인에게 메시지를 보낸다. | 알림 시각에 사용자의 카카오톡으로 메시지가 도착한다. |
| M8 | AI 생성물 표기 | AI가 생성한 알림 문구에 AI 생성물임을 표기한다. | 알림 목록 카드와 발송 메시지 모두에 표기가 보인다. |

### 2-2. 확장 기능 (구현 완료)

| ID | 기능 | 설명 |
|---|---|---|
| E1 | 알림 종류 구분 | 출발 알림(trip)과 시각 알림(reminder)을 구분해 처리한다. |
| E2 | 반복 알림 | 매일, 평일마다 반복되는 알림을 지원한다. |
| E3 | 조건 알림 | 강수확률과 기온 조건을 만족할 때만 발송한다. 조건은 `{type, op, value}` 형식으로 통일한다. |
| E4 | 알림 삭제 | 등록한 알림을 목록에서 삭제한다. |
| E5 | 발송 상태 관리 | 대기 중, 반복 중, 발송 중, 발송 완료, 기간 만료 상태를 관리하고 화면에 표시한다. |
| E6 | 중복 발송 방지 | 발송에 성공하면 기록을 남겨 같은 알림이 두 번 발송되지 않도록 한다. |

### 2-3. 알림 데이터 항목

| 항목 | 설명 |
|---|---|
| alert_id | 알림 고유 식별자 |
| user_id | 카카오 사용자 식별자 |
| kind | 알림 종류 (trip, reminder) |
| departure, destination | 출발지, 도착지 |
| location | 시각 알림의 장소 정보 |
| arrival_at | 도착 시각 |
| notify_at | 알림 발송 시각 |
| notify_mode | 알림 기준 (departure 등) |
| condition | 발송 조건 `{type, op, value}` |
| repeat | 반복 주기 (none, daily, weekdays) |
| message | AI가 해석한 알림 내용 |
| final_message | 발송 시점에 생성된 최종 문구 |
| status, sent | 발송 상태와 발송 여부 |
| created_at, updated_at | 생성 시각, 수정 시각 |

### 2-4. API 목록

| 구분 | 메서드와 경로 | 용도 |
|---|---|---|
| 인증 | GET `/api/auth/kakao/login` | 카카오 인증 페이지로 이동 |
| 인증 | GET `/api/auth/kakao/callback` | 인증 코드 수신 및 토큰 발급 |
| 인증 | GET `/api/auth/kakao/me` | 세션 쿠키로 로그인 상태 확인 |
| 인증 | POST `/api/auth/kakao/logout` | 로그아웃 |
| 알림 | POST `/api/alerts/natural` | 자연어 문장으로 알림 등록 |
| 알림 | GET `/api/alerts` | 알림 목록 조회 |
| 알림 | GET `/api/alerts/{alert_id}` | 알림 상세 조회 |
| 알림 | DELETE `/api/alerts/{alert_id}` | 알림 삭제 |
| 내부 | GET `/api/internal/alerts/due` | 발송 대상 알림 조회 (n8n 전용) |
| 내부 | POST `/api/internal/alerts/{alert_id}/dispatch` | 알림 발송 요청 (n8n 전용) |

내부 API는 `X-Internal-Key` 헤더 인증을 적용한다.


## 3. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 접근성 | 외부에서 접속 가능하도록 Render에 배포한다. 프론트엔드를 백엔드에서 함께 제공해 쿠키와 CORS 문제를 피한다. |
| 호환성 | 모바일과 PC의 최신 웹 브라우저에서 동작한다. |
| 보안 | API 키와 비밀 값은 환경변수로 관리하고 저장소에 올리지 않는다. 로그인 세션은 HttpOnly 쿠키로 유지하고, 내부 API는 헤더 인증으로 보호한다. |
| 데이터 | 사용자 정보와 알림은 Firestore에 저장한다. 보관 기간은 서비스 제공에 필요한 최소한으로 한다. |
| 운영 | 발송 판단은 n8n Cloud에서 10분 주기로 수행한다. 발송 실패 시 재시도하고, 도착 시각이 지난 알림은 만료 처리한다. |
| 가용성 | 무료 플랜 특성상 일정 시간 요청이 없으면 서버가 대기 상태가 되어 첫 응답이 지연될 수 있다. 10분 주기 호출로 완화한다. |
| 안정성 | AI 문구 생성이 실패하면 기본 문구로 대체해 발송한다. 알림 자체가 누락되지 않도록 한다. |
| 개인정보 | 수집 항목과 이용 목적을 사전에 안내하고 동의를 받는다. 테스트 기록에는 실명 대신 식별 기호를 사용한다. |

### 4-3. 외부 API 연동 구조

1) 카카오 로그인 및 메시지 연동

- 인증 방식: OAuth 2.0
- 로그인 제공자: Kakao
- Redirect URI (로컬 개발 환경): `http://localhost:8000/api/auth/kakao/callback`
- 인증 정보: Access Token 및 Refresh Token
- 메시지 전송 방식: 카카오톡 나에게 보내기 API
- 메시지 전송 동의항목: `talk_message`

※ 실제 배포 시 배포 서버 주소에 맞는 Redirect URI 별도 등록 필요

2) 카카오 토큰 관리

- Access Token 발급 및 갱신
- Refresh Token을 활용한 인증 유지
- 사용자별 토큰 저장 및 관리는 Firestore 연동 예정

### 4-5. 기술적 의사결정 및 검토 사항
1) 카카오톡 알림 발송 방식 선정

    - **검토 대상**
        - [방식1] 카카오톡 채널을 통한 사용자 알림 발송
        - [방식2] 카카오톡 메시지 API를 통한 사용자 본인에게 메시지 발송

    - **최종 결정**
        - 카카오톡 메시지 API의 '나에게 보내기' 기능을 활용하여 각 사용자가 본인의 카카오톡으로 외출 알림을 받는 방식으로 결정하였다.

    - **선정 이유**
        - 카카오톡 채널을 통한 메시지 발송은 별도의 비즈메시지 연동 및 권한 확보가 필요
        - 마감 내 MVP 구현 가능성과 API 접근성 고려
        - 사용자별 카카오 로그인 및 메시지 발송 동의를 통한 알림 전달 가능

    - **추후 검토 사항**
        - Firestore 기반 사용자별 토큰 저장 및 관리
        - 토큰 만료 시 자동 갱신 처리
        - 예약 시간에 따른 자동 메시지 발송 연동
        - API 이용 제한 및 메시지 발송 정책 확인
        - 채널 발송 방식의 추가 도입 필요성
